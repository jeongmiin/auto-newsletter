# UI를 크게 고칠 때 — 비용이 새는 곳과 되풀이된 실수

2026-09-14~16 AI 도구 패널(웹 링크 생성 · 다국어 번역)을 Figma대로 갈아엎으면서 **실제로 겪은**
문제만 모았다. 기능은 멀쩡히 동작하는데 조용히 망가지는 종류라 눈으로도, 기존 테스트로도 안 잡혔다.

---

## 1. 외부 API 전송량 — 가장 비싸게 치른 실수

**무슨 일이 있었나.** 리치 텍스트의 굵게·링크를 지키려고 값을 **HTML째** 번역기에 보내도록 바꿨다.
기능은 완벽히 동작했다. 그런데 Azure Translator는 **태그와 `style` 속성도 글자로 센다.**

```
화면에 적힌 글자 수   2,544자      ← 사용자가 보는 숫자
실제로 보낸 글자 수  17,134자 (7배) ← 한도에서 깎이는 숫자
```

이 프로젝트의 뉴스레터 HTML은 거의 모든 태그에
`style="margin:0;font-size:15px;line-height:1.6;color:#4e5968;letter-spacing:-0.15px;"`가 붙어 있어,
글자 20자짜리 문단이 250자가 된다. 무료 한도(월 200만 자)가 7배 빨리 닳고 속도 제한(429)에 걸렸다.
**사용자가 "왜 실패해?"라고 묻고 나서야 알았다.**

### 규칙

- **번역기에 보내는 모양(payload)을 바꾸면 반드시 전송량을 재라.** 화면에 적히는 숫자와 다르다.
- 잰 다음 **"무료 한도로 몇 번 쓸 수 있나"까지 계산해서 사용자에게 알려라.** 배수만으로는 감이 안 온다.
- 지키는 장치: **`src/utils/__tests__/translationPayload.test.ts`** — 실제 템플릿을 읽어
  `보이는 글자 대비 전송 배수 ≤ 3`을 검사한다. 지금은 2.2~2.4배.
  - 이 테스트가 깨지면 **기능이 고장 난 게 아니라 번역 비용이 뛴 것**이다.
  - **상한 숫자를 올려서 통과시키지 말 것.** 왜 늘었는지 먼저 밝히고, 사용자에게 횟수로 보고한 뒤 결정.

### 지금 구조 (2026-09-16)

- **값 하나 = 카드 한 장.** 문장마다 쪼개지 않는다(문맥이 살아 번역 품질이 낫고, 화면도 쓴 모양대로).
- 리치 텍스트는 **속성을 떼고 번호만 남긴 뼈대**를 보낸다 — `newsletterTranslation.toSkeleton()`.
  `<p style="…긴 속성…">` → `<p i="0">`. 돌아오면 번호를 보고 원래 속성을 되붙인다(`restoreSkeleton`).
- 번호가 없거나 모르는 번호면 **속성 없이 둔다.** 서식 하나를 잃을지언정 엉뚱한 서식이 붙지 않게.
- 더 줄이려 해 봤자 남은 건 태그 이름 값이다(측정함): 인라인 없는 값만 평문으로 보내면 −8%,
  번호를 빼면 −14%(대신 순서가 바뀌면 서식이 어긋남), 예전처럼 조각내면 −40%(카드가 쪼개지고 번역이 어색해짐).
  **건드릴 값이 아니다.**

### 로컬에서 번역 쓰기

터미널 **두 개**가 필요하다. 프록시가 없으면 Vite가 `/api/translate`에서 연결 거부 → **500**.

```
npm run dev              # 5173
npm run proxy:translate  # 5175 — Azure 키를 브라우저에 노출하지 않으려는 별도 프로세스
```

## 2. CSS 클래스 이름 충돌

새로 만든 `.ts-head`가 `src/assets/panels.css`의 공용 유틸
(`.row-between, .qa-foot, .ts-head, .tbl-toolbar, …{ display:flex; align-items:center; justify-content:space-between }`)과
겹쳐, 머리글이 통째로 **가운데로 쏠렸다.** 원인을 찾는 데 한참 걸렸다(내 스코프 스타일에는 그런 값이 없으니).

> **새 클래스를 만들기 전에 이름이 비었는지 확인한다.**
> `grep -rn "\.클래스명\b" src/ --include=*.css --include=*.vue`
> panels.css에는 여러 컴포넌트가 이름만 빌려 쓰는 **공용 묶음 선택자**가 있다. scoped 스타일이라고 안전하지 않다.

## 3. `<script setup>` 안의 변수는 컴포넌트마다 새로 만들어진다

패널보다 오래 살아야 할 기준값을 `<script setup>` 안에 두고 "모듈 스코프"라고 착각했다.
좌측 패널은 레일 메뉴를 옮기면 **통째로 사라졌다 다시 생긴다.** 그래서 돌아올 때마다 기준이 지워져
"내용이 변경되었어요" 안내가 **한 번도 뜨지 않았다.**

> 패널보다 오래 살아야 하는 값은 **별도 `<script>` 블록**(진짜 모듈 스코프)이나 **스토어**에 둔다.
> `AiToolsPanel.vue`의 `linkBaseline`이 그 예이며 주석으로 못 박아 뒀다.

---

## 4. `mounted`에서 DOM 치수를 재면 이르다

번역문 칸을 내용만큼 늘리는 코드를 `mounted`에 뒀는데, 그 시점엔 `v-model`이 값을 넣기 전이라
**빈 칸**을 재고 최소 높이(130px)에 굳었다. 긴 번역문이 계속 잘려 보였다.

> 붙자마자 한 번, **`requestAnimationFrame`으로 다음 프레임에 한 번 더** 잰다.
> 웹폰트가 늦게 와서 줄 수가 달라지는 것도 이때 함께 잡힌다.

---

## 5. `Number(null)`·`Number('')`은 `0`이다

뼈대에 번호가 없는 태그가 **0번 속성**을 가져가 엉뚱한 색이 붙었다. "없음"과 "0번"을 구분해야 한다.

```ts
const raw = el.getAttribute('i')
const own = raw !== null && /^\d+$/.test(raw) ? attrs[Number(raw)] : undefined
```

## 6. 캔버스로 이동시킬 때 `selectModule`을 쓰지 말 것

번역 카드를 눌러 캔버스를 그 모듈로 옮기려고 `moduleStore.selectModule()`을 쓰면,
좌측 패널이 **속성 편집으로 전환되어 지금 보던 화면이 통째로 사라진다**(`AppLayout`의 `hasSelection`).

> 스크롤만 하려면 `document.getElementById('canvas-module-' + id)?.scrollIntoView(...)`.

## 7. Figma 에셋 다루기

- **회색 상자는 플레이스홀더일 수 있다.** "웹 링크 생성됨" 화면의 큰 아이콘이 Figma에서 회색 링크
  네모로 보였는데, 이는 못 불러온 이미지였다. 그대로 옮기지 말고 프로젝트가 이미 쓰는 에셋으로 대체하고
  **사용자에게 그 판단을 알린다.**
- **Figma PNG 내보내기에는 흰 배경이 깔린다.** 투명이 필요하면 SVG를 받아 직접 굽는다
  (Playwright + `omitBackground: true`). 파란 배경 위에 흰 네모가 생겨서 알았다.
- 큰 SVG(수백 KB)를 그대로 싣지 말고 표시 크기의 3~4배 PNG로 굽는다(292KB → 15KB).
