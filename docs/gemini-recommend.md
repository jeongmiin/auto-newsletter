# Gemini 모듈 조합 추천 연결

AI 도구의 '모듈 조합 추천(만들기)'은 번역·맞춤법 검사와 같은 길로 호출한다: `Vue 앱 → 프록시 → Gemini API`.
Gemini 키는 프록시(로컬은 `.env.local`, 배포본은 Worker 시크릿)에만 두고, `VITE_RECOMMEND_URL`에는
공개 프록시 주소만 넣는다. 프록시는 번역과 **같은 서버**다(`/api/translate` 옆에 `/api/recommend`).
키 하나로 셋 다 돈다 — 무료 한도(하루 요청 수)도 셋이 **같이** 쓴다.

## 무엇을 하나

빈 템플릿에서 시작할 때 "어떤 모듈을 어떤 순서로 놓지?"를 덜어 준다.

1. 분야(팀에서 자동으로 채움) · 목적(사전등록 안내 / 개막 D-day / 참가기업 모집 / 부대행사 안내 / 결과 보고) ·
   행사 정보(행사명·일정·장소·핵심 메시지)를 보낸다 — 요청 **1회**.
2. 우리 빌더의 **조립형 모듈만으로** 짠 구성안 2~3개가 온다. 머리는 헤더 셋(뉴스 헤드라인·기본·이미지형) 중
   하나, 본문 3~6개, 꼬리는 푸터(모델이 고르지 않고 화면이 늘 붙인다).
3. 하나를 고르면 헤더 → 본문 → 푸터 순으로 캔버스에 깔고 **초안 문구**까지 채운다. Ctrl+Z 한 번으로 되돌아간다.

모델이 모듈을 지어내지 못하게 모듈 id는 응답 스키마의 enum으로 묶는다(`scripts/recommend-core.mjs`의
`CATALOG`). 새 조립형 모듈을 추천에 넣으려면 거기에 한 줄 더하고 `moduleStore.composedBuilderMap`에
같은 키가 있는지 확인한다. 문구는 그룹 멤버를 순서대로 훑으며 굵은 글 → 타이틀, 일반 글 → 본문,
버튼 → 버튼, 인라인 텍스트 → 라벨로 넣는다(`src/utils/newsletterRecommend.ts`).

## 실측 (2026-10-16, 3.5 Flash Lite)

코리아빌드위크 2026 가짜 행사 정보로 목적 다섯 가지를 한 번씩 받았다.

| | 결과 |
|---|---|
| 응답 시간 | 4~5.5초 |
| 구성안 수 | 모두 2개 |
| 모듈 선택 | 전부 카탈로그 안. 목적에 맞게 갈렸다(사전등록은 이미지형 헤더 + 큰 버튼, 부대행사는 2단 카드) |
| 문구 | 행사 정보의 일정·장소·프로그램을 그대로 씀. 모르는 값은 [일정]처럼 비움 |
| 고칠 점 | 결과 보고에 사전등록 버튼을 달았다 → 프롬프트에 규칙 추가. 적힌 일정을 [일정]으로 비운 경우가 있어 "적힌 건 그대로" 규칙 추가 |

## 로컬 실행

번역과 같다 — `.env.local`에 `GEMINI_API_KEY`를 넣고 두 터미널에서 각각:

```bash
npm run proxy:translate   # 127.0.0.1:5175 — /api/translate · /api/proofread · /api/recommend
npm run dev               # Vite가 /api/recommend 를 프록시로 넘긴다(vite.config.ts)
```

프록시 코드나 `.env.local`을 고치면 프록시를 다시 켠다.

## 배포

Worker(`scripts/translate-worker.mjs`)가 `/api/recommend`도 받는다. 코드를 고쳤으면 다시 배포한다:

```bash
npm run deploy:translate
```

`.env.production`의 `VITE_RECOMMEND_URL`은 Worker 주소 + `/api/recommend`다.

## 한도

무료 등급은 **프로젝트·모델별 하루 요청 수**로 센다(번역 2~3회, 맞춤법 검사 1회, 추천 1회가 한 바구니).
한도를 넘으면 과금 없이 429가 오고 앱은 "오늘 쓸 수 있는 무료 추천 횟수를 모두 썼어요"라고 안내한다.
정확한 수는 AI Studio의 사용량·한도 화면에서 본다(docs/gemini-translate.md).
